## 2. 数据类型详细设计

### 2.1 自定义类型

```solidity
// LibOrder.sol
type OrderKey is bytes32;

// RedBlackTreeLibrary.sol
type Price is uint128;
```

Price 与 OrderKey 使用 Solidity 0.8.19 的 user-defined value type 封装，避免与普通 uint/bytes32 混淆。

### 2.2 枚举定义

```solidity
// LibOrder.sol
enum Side {
    List,   // 0 - 卖单
    Bid     // 1 - 买单
}

enum SaleKind {
    FixedPriceForCollection,  // 0 - 集合固定价（仅 Bid）
    FixedPriceForItem         // 1 - 单品固定价（List 必须；Bid 可选）
}
```

### 2.3 结构体定义

#### Order（订单）

| 字段 | Solidity 类型 | 存储大小 | 说明 |
|------|--------------|----------|------|
| side | Side (uint8) | 1 byte | 订单方向 |
| saleKind | SaleKind (uint8) | 1 byte | 销售类型 |
| maker | address | 20 bytes | 创建者地址 |
| nft | Asset | 见下 | NFT 资产信息 |
| price | Price (uint128) | 16 bytes | 单价（wei） |
| expiry | uint64 | 8 bytes | 过期时间戳，0=永不过期 |
| salt | uint64 | 8 bytes | 唯一性盐值 |

#### Asset（NFT 资产）

| 字段 | 类型 | 说明 |
|------|------|------|
| tokenId | uint256 | ERC721 Token ID |
| collection | address | ERC721 合约地址 |
| amount | uint96 | 数量 |

#### DBOrder（存储用订单）

| 字段 | 类型 | 说明 |
|------|------|------|
| order | Order | 完整订单数据 |
| next | OrderKey | 同价位链表的下一个 orderKey |

#### OrderQueue（同价队列）

| 字段 | 类型 | 说明 |
|------|------|------|
| head | OrderKey | 队列头 |
| tail | OrderKey | 队列尾 |

#### EditDetail / MatchDetail（批量操作参数）

```solidity
struct EditDetail {
    OrderKey oldOrderKey;
    Order newOrder;
}

struct MatchDetail {
    Order sellOrder;
    Order buyOrder;
}
```

### 2.4 常量

| 常量 | 值 | 位置 | 说明 |
|------|-----|------|------|
| ORDERKEY_SENTINEL | 0x0 | LibOrder | 链表/返回值哨兵 |
| TOTAL_SHARE | 10000 | LibPayInfo | 费率基数（万分比） |
| MAX_PROTOCOL_SHARE | 1000 | LibPayInfo | 最大协议费率（10%） |
| CANCELLED | type(uint256).max | OrderValidator | 订单取消标记 |
| EIP_1271_MAGIC_VALUE | 0x1626ba7e | OrderValidator | EIP-1271 签名验证魔数 |

### 2.5 EIP-712 类型哈希

```solidity

ASSET_TYPEHASH = keccak256("Asset(uint256 tokenId,address collection,uint96 amount)")

    "Order(uint8 side,uint8 saleKind,address maker,Asset nft,uint128 price,uint64 expiry,uint64 salt)"
```

## 3. 订单哈希算法

### 3.1 Asset 哈希

```
hash(asset) = keccak256(abi.encode(ASSET_TYPEHASH, tokenId, collection, amount))
```

### 3.2 Order 哈希（OrderKey）

```
hash(order) = keccak256(abi.encodePacked(
    ORDER_TYPEHASH,
    side,
    saleKind,
    maker,
    hash(nft),
    Price.unwrap(price),
    expiry,
    salt
))
```

OrderKey 作为订单的唯一标识，同时用于 Vault 资产索引和 filledAmount 状态追踪。

## 4. 存储布局设计

### 4.1 OrderStorage 存储

```solidity
mapping(OrderKey => DBOrder) public orders;
// 订单主表：orderKey → { order, next }

mapping(address => mapping(Side => RedBlackTreeLibrary.Tree)) public priceTrees;
// 价格索引：collection → side → 红黑树

mapping(address => mapping(Side => mapping(Price => OrderQueue))) public orderQueues;
// 同价队列：collection → side → price → { head, tail }
```

**Tree 内部结构（RedBlackTreeLibrary）：**

```solidity
struct Tree {
    Price root;
    mapping(Price => Node) nodes;
}
struct Node {
    Price parent;
    Price left;
    Price right;
    uint8 red;  // RED_TRUE=1, RED_FALSE=2
}
```

### 4.2 OrderValidator 存储

```solidity
mapping(OrderKey => uint256) public filledAmount;
// 0 = 未成交
// 1 ~ amount-1 = 部分成交（买单场景）
// amount = 完全成交
// type(uint256).max = 已取消
```

### 4.3 ProtocolManager 存储

```solidity
uint128 public protocolShare;
```

### 4.4 EasySwapOrderBook 存储

```solidity
address private immutable self;  // 部署地址，用于 delegatecall 检测
```

## 5. OrderStorage 详细设计

### 5.1 _addOrder — 添加订单

**输入：** `Order memory order`

**处理流程：**

1. 计算 `orderKey = LibOrder.hash(order)`
2. 检查 `orders[orderKey].order.maker != address(0)`，若已存在则 revert `CannotInsertDuplicateOrder`
3. 获取 `priceTree = priceTrees[collection][side]`
4. 若 price 不在树中，执行 `priceTree.insert(price)`
5. 获取 `orderQueue = orderQueues[collection][side][price]`
6. 若 queue 为空（head 为 SENTINEL），初始化 head=tail=orderKey
7. 否则，将新 orderKey 追加到 tail：
   - `orders[oldTail].next = orderKey`
   - `orderQueue.tail = orderKey`
8. 写入 `orders[orderKey] = DBOrder(order, SENTINEL)`

**返回值：** `OrderKey orderKey`

**时间复杂度：** O(log n) 红黑树插入 + O(1) 链表追加

### 5.2 _removeOrder — 移除订单

**输入：** `Order memory order`（用于匹配定位）

**处理流程：**

1. 获取 `orderQueue = orderQueues[collection][side][price]`
2. 从 head 开始遍历链表，匹配条件：
   - maker、saleKind、expiry、salt、tokenId、amount 全部一致
3. 找到后：
   - 若为 head：`orderQueue.head = dbOrder.next`
   - 否则：`orders[prevOrderKey].next = dbOrder.next`
   - 若为 tail：`orderQueue.tail = prevOrderKey`
   - `delete orders[foundKey]`
4. 若 queue 变空（head 为 SENTINEL）：
   - 删除 orderQueue 映射项
   - 从 priceTree 中 remove(price)

**返回值：** `OrderKey orderKey`（被移除的 key）

**失败：** 未找到匹配订单 revert `"Cannot remove missing order"`

### 5.3 getBestPrice — 获取最优价格

```solidity
function getBestPrice(address collection, Side side) public view returns (Price)
```

| Side | 返回值 | 含义 |
|------|--------|------|
| Bid | priceTree.last() | 最高买价 |
| List | priceTree.first() | 最低卖价 |

### 5.4 getNextBestPrice — 获取次优价格

```solidity
function getNextBestPrice(address collection, Side side, Price price) public view returns (Price)
```

- 若 price 为空：返回最优价（同 getBestPrice）
- Bid：`priceTree.prev(price)` — 次高价
- List：`priceTree.next(price)` — 次低价

### 5.5 getBestOrder — 查询最优有效订单

**输入：** collection, tokenId, side, saleKind

**算法：**

```
price = getBestPrice(collection, side)
while price 非空:
    orderQueue = orderQueues[collection][side][price]
    orderKey = orderQueue.head
    while orderKey 非 SENTINEL:
        dbOrder = orders[orderKey]
        // 过滤1: Bid + FixedPriceForItem → 跳过 tokenId 不匹配的 Item Bid
        // 过滤2: Bid + FixedPriceForCollection → 跳过 Item Bid
        // 过滤3: 跳过过期订单
        if 通过所有过滤:
            return dbOrder.order
        orderKey = dbOrder.next
    price = getNextBestPrice(collection, side, price)
return 空 Order
```

### 5.6 getOrders — 分页查询订单

**输入：** collection, tokenId, side, saleKind, count, price, firstOrderKey

**算法：**

```
resultOrders = new Order[](count)
if price 为空: price = getBestPrice()
else if firstOrderKey 为 SENTINEL: price = getNextBestPrice(price)

i = 0
while price 非空 且 i < count:
    遍历 orderQueue 链表（支持 firstOrderKey 游标定位）
    应用与 getBestOrder 相同的过滤规则
    resultOrders[i] = dbOrder.order
    nextOrderKey = dbOrder.next
    i++
    price = getNextBestPrice(price)

return (resultOrders, nextOrderKey)
```

## 6. OrderValidator 详细设计

### 6.1 _validateOrder

**输入：** `Order memory order`, `bool isSkipExpiry`

**校验规则：**

| 条件 | 错误信息 |
|------|----------|
| maker == address(0) | "OVa: miss maker" |
| !isSkipExpiry 且 expiry != 0 且 expiry <= block.timestamp | "OVa: expired" |
| salt == 0 | "OVa: zero salt" |
| side == List 且 collection == address(0) | "OVa: unsupported nft asset" |
| side == Bid 且 price == 0 | "OVa: zero price" |

### 6.2 filledAmount 状态机

```
                    ┌─────────┐
                    │    0    │  初始/未成交
                    └────┬────┘
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
      ┌──────────┐ ┌──────────┐ ┌──────────────┐
      │ 1~amount-1│ │  amount  │ │ CANCELLED    │
      │ 部分成交   │ │ 完全成交  │ │ (uint256.max)│
      └──────────┘ └──────────┘ └──────────────┘
```

- `_getFilledAmount(orderKey)`：读取 filledAmount，若为 CANCELLED 则 revert
- `_updateFilledAmount(newAmount, orderKey)`：更新 filledAmount，禁止设为 CANCELLED
- `_cancelOrder(orderKey)`：设 filledAmount = CANCELLED

### 7.2 makeOrders

```solidity
function makeOrders(Order[] calldata newOrders)
    external payable whenNotPaused nonReentrant
    returns (OrderKey[] memory newOrderKeys)
```

**伪代码：**

```
newOrderKeys = new OrderKey[](newOrders.length)
ETHAmount = 0

for each order in newOrders:
    buyPrice = (order.side == Bid) ? price * amount : 0
    newOrderKey = _makeOrderTry(order, buyPrice)
    newOrderKeys[i] = newOrderKey
    if newOrderKey != SENTINEL:
        ETHAmount += buyPrice

if msg.value > ETHAmount:
    refund(msg.value - ETHAmount)
```

### 7.3 _makeOrderTry

**前置条件（全部满足才创建，否则 Skip）：**

| # | 条件 |
|---|------|
| 1 | order.maker == msg.sender |
| 2 | Price.unwrap(order.price) != 0 |
| 3 | order.salt != 0 |
| 4 | order.expiry > block.timestamp \|\| order.expiry == 0 |
| 5 | filledAmount[hash(order)] == 0 |

**List 分支：**

- 要求 `nft.amount == 1`，否则返回 SENTINEL
- 调用 `Vault.depositNFT(orderKey, maker, collection, tokenId)`
- 调用 `_addOrder(order)`

**Bid 分支：**

- 要求 `nft.amount > 0`，否则返回 SENTINEL
- 调用 `Vault.depositETH{value: ETHAmount}(orderKey, ETHAmount)`
- 调用 `_addOrder(order)`

### 7.4 _cancelOrderTry

**前置条件：**

- order.maker == msg.sender
- filledAmount[orderKey] < order.nft.amount

**处理：**

1. 读取 order = orders[orderKey].order
2. `_removeOrder(order)` — 从订单簿移除
3. List：Vault.withdrawNFT → 退还 NFT
4. Bid：计算 availAmount = amount - filledAmount，Vault.withdrawETH(price × availAmount)
5. `_cancelOrder(orderKey)` — 标记 CANCELLED
6. emit LogCancel

### 7.5 _editOrderTry

**不可修改字段校验：**

```
oldOrder.saleKind == newOrder.saleKind
oldOrder.side == newOrder.side
oldOrder.maker == newOrder.maker
oldOrder.nft.collection == newOrder.nft.collection
oldOrder.nft.tokenId == newOrder.nft.tokenId
filledAmount[oldOrderKey] < oldOrder.nft.amount
```

**新订单校验：**

```
newOrder.maker == msg.sender
newOrder.salt != 0
newOrder.expiry > block.timestamp || newOrder.expiry == 0
filledAmount[hash(newOrder)] == 0
```

**处理流程：**

1. 记录 oldFilledAmount
2. `_removeOrder(oldOrder)` + `_cancelOrder(oldOrderKey)` + emit LogCancel
3. `newOrderKey = _addOrder(newOrder)`
4. List：Vault.editNFT(oldKey, newKey)
5. Bid：计算 oldRemainingPrice 和 newRemainingPrice，Vault.editETH（多退少补）
6. emit LogMake

**返回值：** (newOrderKey, deltaBidPrice)

### 7.6 _matchOrder — 核心撮合逻辑

**第一步：匹配校验 `_isMatchAvailable`**

| # | 条件 | 错误 |
|---|------|------|
| 1 | sellOrderKey != buyOrderKey | "HD: same order" |
| 2 | sellOrder.side == List && buyOrder.side == Bid | "HD: side mismatch" |
| 3 | sellOrder.saleKind == FixedPriceForItem | "HD: kind mismatch" |
| 4 | sellOrder.maker != buyOrder.maker | "HD: same maker" |
| 5 | 资产匹配（见下） | "HD: asset mismatch" |
| 6 | 双方均未完全成交 | "HD: order closed" |

**资产匹配规则：**

```
if buyOrder.saleKind == FixedPriceForCollection:
    pass  // 不要求 tokenId 一致
else:
    require sellOrder.nft.collection == buyOrder.nft.collection
    require sellOrder.nft.tokenId == buyOrder.nft.tokenId
```

**第二步：分角色执行**

#### 场景 A：卖方发起（msg.sender == sellOrder.maker）

```
require msg.value == 0

isSellExist = orders[sellOrderKey].maker != address(0)
_validateOrder(sellOrder, isSellExist)    // 链上卖单跳过 expiry
_validateOrder(orders[buyOrderKey].order, false)

fillPrice = buyOrder.price

if isSellExist:
    _removeOrder(sellOrder)
    _updateFilledAmount(sellOrder.nft.amount, sellOrderKey)  // 完全成交

_updateFilledAmount(filledAmount[buyOrderKey] + 1, buyOrderKey)  // 买单 +1

Vault.withdrawETH(buyOrderKey, fillPrice, address(this))
protocolFee = fillPrice * protocolShare / TOTAL_SHARE
sellOrder.maker.transfer(fillPrice - protocolFee)

if isSellExist:
    Vault.withdrawNFT(sellOrderKey, buyOrder.maker, collection, tokenId)
else:
    Vault.transferERC721(sellOrder.maker, buyOrder.maker, sellOrder.nft)
```

#### 场景 B：买方发起（msg.sender == buyOrder.maker）

```
isBuyExist = orders[buyOrderKey].maker != address(0)
_validateOrder(orders[sellOrderKey].order, false)
_validateOrder(buyOrder, isBuyExist)

buyPrice = buyOrder.price
fillPrice = sellOrder.price

if !isBuyExist:  // 链下买单
    require msg.value >= fillPrice
else:  // 链上买单
    require buyPrice >= fillPrice
    Vault.withdrawETH(buyOrderKey, buyPrice, address(this))
    _removeOrder(buyOrder)
    _updateFilledAmount(filledAmount[buyOrderKey] + 1, buyOrderKey)

_updateFilledAmount(sellOrder.nft.amount, sellOrderKey)

protocolFee = fillPrice * protocolShare / TOTAL_SHARE
sellOrder.maker.transfer(fillPrice - protocolFee)

if buyPrice > fillPrice:
    buyOrder.maker.transfer(buyPrice - fillPrice)  // 退还差价

Vault.withdrawNFT(sellOrderKey, buyOrder.maker, collection, tokenId)

costValue = isBuyExist ? 0 : buyPrice
```

#### 场景 C：其他地址

```
revert "HD: sender invalid"
```

### 7.7 matchOrders — 批量撮合

```solidity
function matchOrders(MatchDetail[] calldata matchDetails)
    external payable whenNotPaused nonReentrant
    returns (bool[] memory successes)
```

**关键设计：**

- 使用 `address(this).delegatecall(...)` 调用 `matchOrderWithoutPayback`
- `matchOrderWithoutPayback` 带有 `onlyDelegateCall` 修饰符
- delegatecall 失败时捕获 error data，emit `BatchMatchInnerError(i, data)`
- 累计 buyETHAmount（仅统计 msg.sender 为买方的 costValue）
- 最后统一退还 `msg.value - buyETHAmount`

**onlyDelegateCall 实现：**

```solidity
address private immutable self = address(this);

function _checkDelegateCall() private view {
    require(address(this) != self);
}
```

在 delegatecall 上下文中，`address(this)` 指向代理合约，而 `self` 是 implementation 地址，两者不同。

## 8. EasySwapVault 详细设计

### 8.1 访问控制

```solidity
modifier onlyEasySwapOrderBook() {
    require(msg.sender == orderBook, "HV: only EasySwap OrderBook");
    _;
}
```

### 8.2 depositETH

```solidity
function depositETH(OrderKey orderKey, uint256 ETHAmount) external payable onlyEasySwapOrderBook
```

- require msg.value >= ETHAmount
- ETHBalance[orderKey] += msg.value

### 8.3 withdrawETH

```solidity
function withdrawETH(OrderKey orderKey, uint256 ETHAmount, address to) external onlyEasySwapOrderBook
```

- ETHBalance[orderKey] -= ETHAmount
- to.safeTransferETH(ETHAmount)

### 8.4 depositNFT

```solidity
function depositNFT(OrderKey orderKey, address from, address collection, uint256 tokenId)
    external onlyEasySwapOrderBook
```

- IERC721(collection).safeTransferNFT(from, address(this), tokenId)
- NFTBalance[orderKey] = tokenId

### 8.5 withdrawNFT

```solidity
function withdrawNFT(OrderKey orderKey, address to, address collection, uint256 tokenId)
    external onlyEasySwapOrderBook
```

- require NFTBalance[orderKey] == tokenId
- delete NFTBalance[orderKey]
- IERC721(collection).safeTransferNFT(address(this), to, tokenId)

### 8.6 editETH

```solidity
function editETH(
    OrderKey oldOrderKey, OrderKey newOrderKey,
    uint256 oldETHAmount, uint256 newETHAmount, address to
) external payable onlyEasySwapOrderBook
```

| 条件 | 行为 |
|------|------|
| old > new | ETHBalance[newKey] = newAmount; 退还 old - new 给 to |
| old < new | require msg.value >= new - old; ETHBalance[newKey] = msg.value + old |
| old == new | ETHBalance[newKey] = oldAmount |

始终：`ETHBalance[oldOrderKey] = 0`

### 8.7 editNFT

```solidity
function editNFT(OrderKey oldOrderKey, OrderKey newOrderKey) external onlyEasySwapOrderBook
```

- NFTBalance[newOrderKey] = NFTBalance[oldOrderKey]
- delete NFTBalance[oldOrderKey]

### 8.8 transferERC721

```solidity
function transferERC721(address from, address to, Asset calldata assets) external onlyEasySwapOrderBook
```

- 直接从 from 转移 NFT 到 to（不经过 Vault 持有，用于链下卖单撮合）

### 8.9 batchTransferERC721

```solidity
function batchTransferERC721(address to, NFTInfo[] calldata assets) external
```

- 无 onlyEasySwapOrderBook 限制
- 从 msg.sender 批量转移 NFT 到 to

## 12. 协议费计算

```solidity
function _shareToAmount(uint128 total, uint128 share) internal pure returns (uint128) {
    return (total * share) / LibPayInfo.TOTAL_SHARE;
}
```

**示例：** protocolShare = 200, fillPrice = 1 ETH

```
protocolFee = 1 ETH × 200 / 10000 = 0.02 ETH (2%)
sellerReceives = 1 ETH - 0.02 ETH = 0.98 ETH
```

协议费留在 OrderBook 合约中，Owner 通过 withdrawETH 提取。

## 16. 边界条件与特殊场景

### 16.1 永不过期订单

`expiry == 0` 表示订单永不过期，校验和查询时均视为有效。

### 16.2 链上 vs 链下订单

| 特征 | 链上订单 | 链下订单 |
|------|----------|----------|
| 存在性 | orders[orderKey].maker != 0 | orders[orderKey].maker == 0 |
| 资产 | 托管在 Vault | 保留在 maker 钱包 |
| 撮合时 NFT | Vault.withdrawNFT | Vault.transferERC721 |
| 撮合校验 | isSkipExpiry = true（卖单） | 正常 expiry 校验 |

### 16.3 买单部分成交

买单 amount 可 > 1，每次撮合 `_updateFilledAmount(filledAmount + 1, orderKey)`。当 filledAmount == amount 时订单完全成交，不再参与撮合。

### 16.4 批量操作部分失败

- makeOrders：失败订单返回 SENTINEL，发出 LogSkipOrder
- cancelOrders：返回 bool[] 标记每笔成败
- editOrders：失败返回 SENTINEL
- matchOrders：返回 bool[]，失败 emit BatchMatchInnerError

### 16.5 msg.value 退还机制

所有 payable 函数均在末尾检查 `msg.value > 实际需要`，多余部分通过 `safeTransferETH` 退还给 msg.sender。
